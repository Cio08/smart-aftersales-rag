### 【考题 01】列表推导式与取模运算
- **考题内容**：对于列表 `data = [10, 15, 20, 25, 30, 35, 40]`，执行 `[x for x in data if x % 2 == 0 and x > 15]` 会输出什么？背后的数学与逻辑是什么？
- **考查核心**：列表推导式、取模运算 `%` 判断奇偶性。
- **标准答案**：
  输出 `[20, 30, 40]`。
  - `x % 2 == 0`：求余数为 0，筛选出所有偶数；
  - `x > 15`：过滤掉小于等于 15 的数值（如 10）；
  - 最终保留既是偶数且大于 15 的元素。

### 【考题 02】字典嵌套安全取值与 `.get()` 机制
- **考题内容**：
  1. 如何从 `user = {"id": 1, "details": {"city": "顺德"}}` 安全读取 `city`？
  2. 如果直接访问不存在的键 `user["age"]` 与 `user.get("age")` 分别会发生什么？
- **考查核心**：字典索引崩溃风险与防御性取值。
- **标准答案**：
  1. 安全读取方式为：`user.get("details", {}).get("city")`。
  2. **致命区别**：
     - `user["age"]` 会直接抛出 `KeyError: 'age'` 异常，未捕获会导致程序奔溃；
     - `user.get("age")` 不会报错，安全返回默认值 `None`。

### 【考题 03】面向对象编程：类、实例与 `self` 的本质
- **考题内容**：
  在 Python 类中，`__init__` 方法的作用是什么？`self` 代表什么？如果有 100 个客户访问系统，内存中会产生什么？
- **考查核心**：类（Class）作为抽象模板 vs 实例（Instance）在内存中的物理分配。
- **标准答案**：
  1. `__init__` 是构造魔法方法，在对象被实例化时自动执行，用于初始化并绑定属于该实例的具体属性。
  2. `self` 代表**当前具体的实例对象自身**（指向该实例在内存中的独立首地址）。
  3. 系统中只有 **1 个 `Customer` 类模板**，但在内存中会为每个独立请求分配 **100 个不同的 `Customer` 对象实例**，互不干扰。

### 【考题 04】HTTP 协议：GET 与 POST 的根本区别与大模型适用性
- **考题内容**：为什么向大模型发起对话请求必须使用 POST，而不能使用 GET？
- **考查核心**：HTTP 请求规范、URL 长度限制与请求体（Request Body）。
- **标准答案**：
  1. **数据载体差异**：GET 请求参数拼接在 URL 的 Query String 中，受浏览器与服务器限制通常不超过 2KB~8KB；POST 的数据存放在请求体（Request Body）中，容量理论上无限制。
  2. **安全性与语义**：大模型对话包含多轮历史、Prompt 模板、System 指令，数据量可达几十 KB 甚至数百 KB，必须使用 POST；且调用大模型会消耗服务算力或生成内容，语义上属于非幂等操作。

### 【考题 05】API Key 鉴权与 HTTP 状态码辨析
- **考题内容**：API Key 的作用是什么？状态码 200、401、404 分别代表什么含义？
- **考查核心**：RESTful API 鉴权机制与标准化状态码。
- **标准答案**：
  - **API Key**：服务提供方为开发者分配的通信凭据（通行密钥），用于身份认证、限流与计费结算。
  - **200 OK**：请求成功，服务端正常返回数据。
  - **401 Unauthorized**：未授权/鉴权失败，通常是 API Key 填写错误、过期或未传递。
  - **404 Not Found**：请求的资源路径不存在（URL 拼写错误或端点不存在）。

### 【考题 06】同步（Sync）与异步（Async）在高并发大模型中的本质差异
- **考题内容**：为什么在等待大模型返回结果的几秒钟内，异步编程能大幅提升系统性能？
- **考查核心**：阻塞 I/O vs 非阻塞 I/O，Python 协程（Coroutine）调度。
- **标准答案**：
  - **同步（Sync）**：当发起网络请求时，主线程被强制阻塞傻等，在这 2~3 秒内无法处理任何其他用户的请求。
  - **异步（Async）**：遇到 `await` 时，Python 自动将该协程挂起，释放 CPU 和线程去并发处理其他排队用户的请求；当大模型的数据网络包到达时，事件循环再唤醒此协程继续执行。
  - **价值**：极大提升单机服务器的高并发吞吐能力与硬件资源利用率。

### 【考题 08】语义向量（Vector Embedding）vs 传统字符精确匹配
- **考题内容**：
  为什么“盘子摸起来油腻”与“餐具洗涤后残留白斑油污”字面无重叠，但向量检索能识别其高度相关？
- **考查核心**：高维语义空间、余弦相似度（Cosine Similarity）。
- **标准答案**：
  1. **传统匹配**（如 `Ctrl+F` 或 SQL `LIKE`）：基于字符精确相等，无字面重叠即判定为无匹配。
  2. **语义向量**：通过大模型将文本投影到数百维的高维向量空间中，语义相近的概念在几何空间中距离极近、夹角极小。
  3. **余弦计算**：当两段文字语义完全一致时，向量夹角为 0，$\cos(0) = 1$。通过点积计算余弦相似度得分，得分越接近 1，语义越契合。

### 【考题 09】RAG 架构链路与防幻觉系统提示词
- **考题内容**：
  RAG 系统的全流程步骤是什么？为什么提示词中必须强调“仅基于参考资料回答，未提及则说明不在手册范围”？
- **考查核心**：RAG 检索增强生成原理、大模型幻觉抑制与企业安全生产红线。
- **标准答案**：
  1. **标准三步法**：

  2. **防幻觉必要性**：大模型倾向于用通识知识“自信地胡编乱造”。在售后维修场景中，如果大模型瞎编拆机排查步骤，可能导致短路起火或触电伤人。必须通过负向约束锁死模型边界，未收录内容一律分流至官方人工。

### 【考题 10】流式生成器：`yield` vs `return` 的底层差异
- **考题内容**：在流式生成函数中，为什么使用 `yield` 能够实现打字机效果，而 `return` 不行？
- **考查核心**：Python 生成器（Generator）、栈帧冷冻与恢复。
- **标准答案**：
  - `return`：函数执行到此处立即终结，销毁本地变量与调用栈，向调用方一次性交付最终结果。
  - `yield`：使函数成为生成器。每次执行到 `yield`，向外界交付一个数据片段，并**就地冷冻（Freeze）函数当前的执行状态与变量现场**。当外界再次请求下一个数据时，函数从暂停处继续执行，从而实现毫秒级打字机推流。

### 【考题 11】Python 装饰器 `@classmethod` 与 `cls` 语义
- **考题内容**：`@classmethod` 的作用是什么？为什么形参是 `cls` 而不是 `self`？
- **考查核心**：类方法 vs 实例方法。
- **标准答案**：
  - 普通方法接收 `self`，代表具体实例，必须先 `obj = A()` 实例化后才能调用；
  - 带有 `@classmethod` 的方法接收 `cls`，代表类本身，无需实例化即可通过 `A.method()` 直接调用，适用于工厂方法、工具类方法或单例服务调度。

### 【考题 12】流式数据包：`delta.content` vs `message.content`
- **考题内容**：在大模型开启 `stream=True` 时，为什么必须从 `chunk.choices[0].delta.content` 中提取文字？
- **考查核心**：流式数据传输协议（Server-Sent Events / Chunk）。
- **标准答案**：
  - 在非流式响应中，模型等待全部回答生成完毕后一次性返回 `message.content`；
  - 在流式模式下，服务端以碎片包推送，每次返回的是增量差量数据 `delta`（增量单词/标点）。此时完整的 `message` 对象尚未封闭，必须读取 `delta.content` 才能获得当前推过来的文字片段。

### 【考题 13】滑动窗口记忆（Session Memory）与 Token 经济学
- **考题内容**：为什么不能把用户过去的 100 轮历史对话全部塞进 Prompt 发给大模型？
- **考查核心**：大模型上下文窗口（Context Window）与商业运营成本。
- **标准答案**：
  1. **技术层面**：全量塞入会迅速撑爆模型的上下文窗口极限，并导致每次调用的网络 I/O 剧增，严重拖慢首字响应速度（TTFT）。
  2. **商业层面**：大模型按 Token 计费。早期几十轮对话中大部分内容对当前问题毫无参考价值，但每次对话都要重复为全量 Token 付费，导致企业运营成本呈指数级飙升。
  3. **工程解法**：采用滑动窗口机制（如只保留最近 3 轮 / 6 条对话），实现低成本与强记忆的黄金平衡。

### 【考题 14】代词消解（Query Rewrite）的必要性
- **考题内容**：用户先问“洗碗机E01怎么修”，紧接着追问“那换这个零件要多少钱”。如果直接把后一句送去向量检索，会发生什么？
- **考查核心**：语义孤岛、代词脱水与搜索召回率。
- **标准答案**：
  向量数据库只负责数学比对，无法获知历史上下文。“这个零件”在向量空间中指向模糊，可能检索出一堆风马牛不相及的说明书切片。必须通过小参数模型结合上下文执行代词消解，将其重写为“洗碗机更换进水螺线管阀要多少钱”，才能精准命中手册。

### 【考题 15】Python 切片语法 Bug：`TypeError: string indices must be integers, not 'str'`
- **考题内容**：
  在 `SessionMemory` 中，把 `history[-self.max_messages:]` 误写成 `history[-self.max_messages]`，为什么会导致遍历时报错 `string indices must be integers`？
- **考查核心**：列表切片（返回列表） vs 单一索引访问（返回字典），以及遍历字典的默认行为。
- **标准答案**：
  1. `[-self.max_messages:]`（带冒号）是**切片**，返回的是截断后的**消息字典列表** `[dict1, dict2]`；
  2. `[-self.max_messages]`（不带冒号）是**下标索引**，返回的是**单个字典** `dict1`；
  3. 当对单个字典执行 `for msg in history:` 时，Python 默认遍历的是字典的 **Key（键名字符串，如 "role"）**；
  4. 循环体内部接着执行 `msg["role"]`，相当于对字符串执行 `"role"["role"]`。由于 Python 字符串只支持整数下标（如 `"role"[0]`），系统当场崩溃抛出 `TypeError: string indices must be integers, not 'str'`。

## 阶段三：AI Agent 协议、工具调度、关系持久化与业务防御

### 【考题 18】Function Calling 通信协议与两阶段交互模型
- **考题内容**：
  1. 当大模型决定调用工具时，它返回给本地 Python 程序的最核心两个字段是什么？
  2. 大模型为什么不自己直接写数据库，而必须通过 Python 本地代码执行？
  3. 为什么本地执行完工具后，必须将结果再次回传给大模型做“第二次调用”？
- **考查核心**：原生 Function Calling 协议、沙盒物理隔离与工具闭环。
- **标准答案**：
  1. 核心字段是 **`name`**（工具函数名）与 **`arguments`**（格式化的 JSON 入参字符串）。
  2. **安全与环境隔离**：大模型云端运行，属于纯文本推理机，在物理上无法触碰宿主机操作系统底层，无权限直接连接本地数据库。Python 作为“手脚与代理网关”，负责校验参数并安全执行本地 I/O。
  3. **两次调用的分工**：
     - **第一次调用**：大模型完成“语义理解与结构化参数抽取”，输出调用指令（不吐人话）；
     - **第二次调用**：大模型拿到真实工具执行结果（工单回执），负责将生硬的数据总结润色为自然、体贴的客户答复。

### 【考题 20】Python 关键字参数解包（`**kwargs`）
- **考题内容**：代码 `book_repair(**func_args)` 中的 `**` 起了什么作用？
- **考查核心**：字典解包（Dictionary Unpacking）。
- **标准答案**：

### 【考题 21】流式网络通信下的工具碎片装配（`tool_calls_accumulator`）
- **考题内容**：流式模式下大模型触发工具调用时，为什么必须在循环中用字典以 `+=` 拼接 `arguments`？
- **考查核心**：流式 Chunk 碎片拼装机制。
- **标准答案**：

### 【考题 22】Python 缩进陷阱：为什么工具调度必须移出 `async for` 循环
- **考题内容**：如果将 `if tool_calls_accumulator:` 误缩进在 `async for chunk in response:` 内部，会导致什么严重后果？
- **考查核心**：循环生命周期与流式结束条件。
- **标准答案**：
  当第一个包含工具调用的 Chunk 到达时，累加器已经非空，缩进在循环内部会导致**每一个后续数据包都触发一次本地工具执行**。在业务中表现为：大模型重复派单两次、插入两条冗余工单，且界面重复打印调度提示。必须将其移至循环外，等流式完全接收完毕后再统一调度。

### 【考题 23】Python 逗号元组陷阱：`sqlite3.ProgrammingError: Error binding parameter 1: type 'tuple' is not supported`
- **考题内容**：在赋值语句 `appliance = arguments.get("appliance", "未知"),` 中，为什么末尾多写了一个逗号会导致 SQLite 报错？
- **考查核心**：Python 隐式元组构造语法与 SQL 参数绑定机制。
- **标准答案**：
  1. 在 Python 中，**逗号才是构造元组的本质**，而不是括号。末尾写了逗号，导致变量 `appliance` 悄悄变成了单元素元组 `("洗碗机",)`，而不是字符串；
  2. 当把这个元组作为占位符参数传给 `cursor.execute("... WHERE appliance = ?", (appliance,))` 时，SQLite 期望接收基础标量（字符串/数字），发现传入了嵌套元组，直接抛出参数绑定类型异常。

### 【考题 24】SQLite 核心三驾马车：`with connect`、`row_factory` 与 `cursor`
- **考题内容**：
  1. `with sqlite3.connect(path) as conn:` 中 `with` 的好处是什么？
  2. `conn.row_factory = sqlite3.Row` 的作用是什么？
  3. `cursor` 充当什么角色？
- **考查核心**：数据库连接上下文管理、行工厂字典化映射与游标执行模型。
- **标准答案**：
  1. **`with` 上下文管理**：代码块退出时自动提交事务（Commit），异常退出时自动安全关闭连接，绝不泄漏数据库句柄或导致文件死锁。
  2. **`row_factory = sqlite3.Row`**：将查询结果由默认的只读数字索引元组，升级为**列名映射行对象**，允许使用 `row["order_no"]` 按列名取值或一键 `dict(row)` 转为标准字典，避免按数字下标取值时因表结构变更导致的越界与错位。
  3. **`cursor`**：游标，负责向数据库发送具体的 SQL 执行指令并暂存执行结果供逐行抓取（`fetchone/fetchall`）。

### 【考题 25】企业级防重单机制：联合多条件比对（Compound Key）
- **考题内容**：在智能报修系统中，为什么不能仅根据手机号来判断是否重复报修？合理的判重条件是什么？
- **考查核心**：真实业务建模与防重复下单逻辑。
- **标准答案**：
  - **仅看手机号的弊端**：同一客户名下可能有多台不同电器（如上午修洗碗机，下午修燃气灶），或者上一单已完成几个月后再次报修。单凭手机号判重会发生严重误拦截，造成用户无法报修与客诉。
  - **工业级联合条件**：`手机号 + 家电品类 + 工单状态（待派工）`。只有相同客户、报修相同电器、且之前的工单仍处于“未履约”处理中，才判定为重复下单并触发温和催单拦截。

### 【考题 27】前端实时看板为什么限制展示最新 8 条？
- **考题内容**：在 `web_ui.py` 侧边栏中，为什么通过 `get_recent_orders(limit=8)` 只取最新 8 条，而不是全量展现？
- **考查核心**：UI 空间管理、浏览器渲染性能与 Streamlit Rerun 机制保护。
- **标准答案**：
  1. **防止界面无限拉长**：若数据积累至数千条，不加限制会导致页面滚轮滑动极长，严重破坏用户体验，并造成浏览器内存卡顿。
  2. **Streamlit 响应机制防御**：Streamlit 的交互模型是用户每次发送对话，整页脚本就会从头到尾重新执行（Rerun）。若每次都把全表数据扫入内存，会对磁盘 I/O 和 CPU 造成不必要的计算浪费。限制 `LIMIT 8` 能够在呈现即时动态的同时，实现极致的性能平衡。

### 【考题 28】权限安全与角色隔离：RBAC 双门户（客户端 vs 调度主管端）设计
- **考题内容**：
  1. 为什么在客户聊天界面，侧边栏不适合像管理后台那样全量拉取成千上万条工单？
  2. 为什么“修改工单状态”与“全局统计报表”必须隔离在“网点主管端”，禁止暴露在客户界面？
- **考查核心**：前端交互性能开销（Streamlit Rerun 机制）与 RBAC（基于角色的权限访问控制）防越权安全规范。
- **标准答案**：
  1. **前端开销与用户体验**：普通用户只需要感知自己的报修进展。若全量加载数万条数据，Streamlit 每次对话交互触发全页重绘（Rerun）时都会执行巨额数据库查询并渲染巨型 DOM 树，引发界面卡死与内存飙升；`limit=8` 是轻量级动态反馈的最佳折中。
  2. **权限安全防越权（RBAC）**：
     - **垂直越权防御**：普通用户绝不可获得修改工单状态的接口，否则会导致恶意取消或伪造完工。
     - **隐私数据隔离**：普通用户界面不得展现全局所有客户的手机号与详细住址，杜绝隐私泄漏风险。
     - **业务责任闭环**：工单流转（待派工 → 处理中 → 已完工）涉及线下调度、配件核销与师傅考勤，必须由主管专岗专权闭环操作。
